# AGENTS.md — правила развития проекта

Личная шпора для Dota 2 на данных Game State Integration. Проект делается «для себя»,
продакшен-требования (упаковка, CI, тесты на всё подряд) не нужны и не добавляются без явного запроса.

## 🔴 Абсолютный запрет: легитимность прежде всего

Это **официальное GSI-приложение**. Так оно должно остаться навсегда.

Допустимо ТОЛЬКО:
- приём POST-пакетов от Dota на локальный HTTP-сервер (`127.0.0.1`) — данные предоставляет сама игра;
- чтение файлов `game/dota/cfg/gamestate_integration/*.cfg` (создание/обновление нашего cfg);
- обычное Win32 API для окна оверлея: стили окон (`WS_EX_TRANSPARENT`, `WS_EX_LAYERED`,
  `WS_EX_NOACTIVATE`), `SetWindowPos`, `GetParent` и т.п.;
- рисование поверх игры через отдельное окно PyQt6 (без вмешательства в игру).

Запрещено КАТЕГОРИЧЕСКИ (превращает легитимное ПО в чит, риск VAC-бана):
- инъекции в процесс dota2.exe (DLL, CreateRemoteThread, hook'и, патчи памяти);
- чтение/запись памяти игры, поиск сигнатур, работа с ProcessMemoryReadBytes;
- перехват трафика игры, подмена пакетов, реплей кнопок/мыши (SendInput в чужое окно);
- автокликеры, скрипты действий в бою, любые «помощи» с реакцией за игрока;
- обращение к сторонним античит-обходным библиотекам;
- использование уязвимостей GSI или Steam-клиента.

Правило для любой новой фичи: **если ей нужны данные, которых нет в GSI-пакете, — фича не делается**
(можно взять из OpenDota/Web API по публичному steamid, но не из памяти игры).
Модуль `overlay.py` имеет право только рисовать; модуль `server.py` — только принимать JSON.

## Архитектура (не нарушать порядок слоёв)

```
Dota GSI -> server.py (только приём) -> state.py (хранилище, потокобезопасно)
                                          ^        ^
                                   timers/*       overlay.py (только рисует)
```

- Новый таймер = один файл в `timers/` с функцией `tick(state)`. Реестр подхватывает его сам.
- Служебные модули в `timers/` начинать с `_` (не станут таймерами).
- `settings.py` — только константы, никакой логики и тяжёлых импортов.
- Таймеры читают state только через публичные методы `GameState` (clock/in_game/items/abilities/upsert/remove).
- Никаких сетевых/дисковых операций внутри `tick()` — тик идёт из цикла QTimer каждые 0.2 с.

## Конвенции

- Комментарии и строки интерфейса — на русском, код — на английском.
- Все времена событий брать из `state.clock()` (секунды от начала матча), не из wall-clock.
- Подсказки: 1–2 строки, крупно, появляются за `LEAD_SECONDS` до события, urgent — цвет из settings.
- Изменения фиксировать в `CHANGELOG.md`; каждый логический шаг — отдельным коммитом (история нужна для откатов после патчей Valve).

## Что уже проверено (аудит v1.0.0)

- Синтаксис всех модулей OK; все таймеры импортируются и дают корректные подсказки на синтетических пакетах.
- Обработаны краевые случаи: отсутствующий game_time (local fallback), отрицательный game_time
  (стратегия/прегейм), смена game_state (часы обнуляются), пустые имена предметов, дубли ТП-слотов.
- Найденные при аудите баги исправлены: см. CHANGELOG «Исправления».
